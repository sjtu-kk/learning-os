# Learning Behavior Protocol

> Scope: the shared learning behavior loop and capture contract for all learning work.
> Authority: when deciding how learning should progress, be recorded, receive feedback, or be promoted, use this protocol.

## First Principles

Learning is not the accumulation of inputs. Its goal is to change future independent performance. Input and output are connected; learning and practice are inseparable. Practice exposes the problems that determine what knowledge to add next.

```text
real demand
-> rough exploration
-> passive knowledge map
-> practice and active invocation
-> questions, associations, and feedback
-> targeted supplementation
-> re-practice
-> reuse, transfer, and creation
-> review and extraction
-> demand and strategy adjustment
```

This is a loop, not a daily checklist. At any moment, identify the current action and choose the smallest valuable next step.

## Exploration And Utilization

The first learning pass only needs a rough framework sufficient to act: what the object is, what problem it solves, its main components, and the unknown regions. This creates a passive knowledge map. Understanding is not mastery.

Once the map supports meaningful practice, stop unbounded exploration and switch to utilization: implementation, experiments, problem solving, explanation, writing, or real delivery. Explore again only when practice exposes a concrete gap, unresolved question, or strategic uncertainty.

New material first expands passive knowledge. It becomes active knowledge only after extraction, selection, application, or transfer can be completed away from the source.

## Three Persistent Record Types

The following content must remain locatable within every learning project, but may be mixed in the same file or directory.

### Materials

Record the courses, papers, blogs, repositories, videos, project artifacts, or AI conversations actually used, and why each relates to the current problem. Exposure to material is not mastery.

### Working Records

Working Records may mix:

- personal impressions and judgments;
- newly encountered knowledge;
- AI discussions;
- implementations, experiments, and failures;
- temporarily unclear hypotheses;
- methods or notes intended for later organization.

The learning workspace should prioritize continuous, recoverable recording. Do not require final domain, memory, maturity, or ownership classification at capture time.

### Questions

Questions are required learning objects, but a standalone question bank is optional. Their lifecycle is:

```text
question
-> current answer or hypothesis
-> status: open / partial / answered / deferred
-> evidence
-> revisit trigger
-> correction or refinement
```

When learning from new material, check whether it affects an existing question. If new evidence changes an answered question's boundary, reopen it.

## Minimum Action Chain

A project learning session does not need to complete the whole loop. It must leave at least:

1. The current real problem or input.
2. One active output or practice attempt.
3. The question or evidence exposed by that attempt.
4. One executable smallest next step.

Feedback must state the evidence used, the current judgment, and why the next step is most valuable. The user's goals, values, deadlines, and constraints define the reward; the agent acts as an adaptive evaluator and controller.

## Review Extraction

Projects retain complete Working Records. Learning OS reviews extract:

- Event: what happened and its evidence;
- Insight: what new understanding the event produced;
- Question movement: a new question, progress on an old question, or a correction;
- Transfer: knowledge or practice connectable to another project;
- Candidate: a possible addition to strategy, planning, method, or a learner record.

Extraction must not rewrite the original record or promote one success automatically into a general method.

## Promotion Threshold

```text
Event -> Insight -> Pattern -> Method -> Capability
```

- `Event`: one sourced practice fact.
- `Insight`: a new interpretation of that fact, possibly provisional.
- `Pattern`: repetition across multiple events with similar boundaries.
- `Method`: a problem, mechanism, steps, evidence, and failure boundaries.
- `Capability`: independent use without prompting, or transfer to a new context.

Changes to strategy, planning, method, or learner state require explicit confirmation. Automation may generate candidates only.

## Periodic Feedback

- Daily connects evidence from the day's projects and reports the exploration/utilization balance, question movement, and next high-value action.
- Monthly checks whether the project portfolio is producing capability growth and decides whether to increase investment, reduce it, pause, or explore.

Multiple projects in one day produce independent evidence batches but one central daily review. The review links evidence and does not copy project notes.

## Specialized Components

PACER determines how knowledge worth retaining should be understood, remembered, and verified. L1-L5 describes current mastery and required evidence. Teach is a persistent teacher that designs the next lesson from mission, learner state, and ZPD. A project adapter locates cross-repository evidence and returns a brief.

These components support the protocol but do not replace it.
