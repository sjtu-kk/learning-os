# Learning OS Agent Constitution

## Purpose
Learning OS turns fragmented inputs into reusable personal capability through exploration, practice, feedback, targeted learning, transfer, and review. The active system uses stable responsibilities, not a lifecycle directory tree.

## Truth and Boot
User instruction > this file > `progress.md` > `system/architecture.md` and protocols > Area/Project READMEs and canonical notes > reviews and imported resources. Boot with this file, `progress.md`, `system/architecture.md`, and `system/index.md`. Use `system/index.md` to route the current action to only the protocol, template, prompt, and owner README needed for the task; do not load unrelated control-plane files.

## Active Structure
`system/` contains implementation rules, templates, and prompts. `resources/` is the sole owner of processed external material; `resources/clippers/` and `resources/raw/` are intake only. `assets/` contains physical attachments. `inbox/notes/` holds unresolved personal notes. `areas/` owns durable domains and `projects/` owns bounded outcomes; each uses `README.md`, `notes/`, and `reviews/`. Central cross-owner reviews live in `reviews/daily/` and `reviews/monthly/`. `archive/` is for retained historical material, never active truth.

## Ownership Rules
One active truth has one physical owner. Cross-area/project relationships use Obsidian wikilinks and queries. Do not create an Area, Project, Tag, or top-level directory without confirmation unless it already exists as an established owner in the migration input. Keep mixed Working Records intact; add Properties, summary, tags, and links rather than generating replacement copies.

## Safety
Before bulk move, delete, or retirement, make a recoverable checkpoint and keep a migration manifest. Do not delete content with unique evidence, judgment, or source value. Do not commit, branch, push, publish, or send external messages unless explicitly requested.
